= @flovven/discovery

Node.js 服务发现组件：注册、注销、查询、订阅，对标 bufgot/discovery 与 ferrite-discovery。

`@flovven/discovery` 为 flovven 生态提供统一的服务发现抽象。业务侧只面向
`ServiceDiscovery` 接口编程，底层可在 Nacos / Eureka / etcd 之间切换，
与 `@flovven/web-client` 的负载均衡、服务发现模式直接对接。

== 特性

* 统一接口：`register` / `deregister` / `resolve` / `subscribe`
* 三种实现：Nacos（官方 SDK）、Eureka（自实现 REST 客户端，无第三方依赖）、etcd（key-value + 租约）
* 自动心跳 / 续约：Eureka 定时续约，etcd 挂租约自动续期，过期即被摘除
* 变更订阅：`subscribe(serviceName, listener)` 返回取消订阅函数
* 纯 ESM，无框架绑定

== 安装

[source,bash]
----
npm i @flovven/discovery
----

Nacos 实现依赖 `nacos-naming`，etcd 实现依赖 `etcd3`，Eureka 实现只依赖全局 `fetch`（Node 18+）。

== 快速开始

[source,ts]
----
import { NacosDiscovery } from '@flovven/discovery';

const discovery = new NacosDiscovery({
  serverAddr: '127.0.0.1:8848',
  namespace: 'public',
});

await discovery.register({
  serviceName: 'flovven-web',
  ip: '10.0.0.11',
  port: 8080,
  weight: 1,
  metadata: { version: '0.1.0' },
});

const instances = await discovery.resolve('flovven-web');
// [{ serviceName: 'flovven-web', id: '10.0.0.11:8080', ip: '10.0.0.11', port: 8080,
//    metadata: { version: '0.1.0' }, weight: 1, healthy: true }]

const off = await discovery.subscribe('flovven-web', (list) => {
  console.log('instances:', list.length);
});

await discovery.deregister({ serviceName: 'flovven-web', ip: '10.0.0.11', port: 8080 });
off();
----

== 核心 API

[options="header"]
|===
| 导出 | 说明

| `ServiceInstance` | 注册入参：`serviceName`、`ip`、`port`、`id?`、`metadata?`、`weight?`、`ephemeral?`
| `ResolvedInstance` | 查询结果：`serviceName`、`id`、`ip`、`port`、`metadata`、`weight`、`healthy`
| `ServiceDiscovery` | 接口：`name`、`register`、`deregister`、`resolve`、可选 `subscribe`
|===

`id` 缺省时各实现统一按 `ip:port` 生成。

== 内置实现

[options="header"]
|===
| 类 | 选项 | 底层与行为

| `NacosDiscovery` | `serverAddr`、`namespace?` | 基于 `nacos-naming`：`registerInstance` / `deregisterInstance` / `getAllInstances`，`subscribe` 走 `subscribe` + `unSubscribe`
| `EurekaDiscovery` | `serverUrl`、`heartbeatMs?`（默认 30000）、`pollMs?`（默认 15000） | 自实现 REST 客户端：`PUT /apps/{APP}` 注册、`PUT /apps/{APP}/{id}` 心跳续约、`DELETE /apps/{APP}/{id}` 注销、`GET /apps/{APP}` 查询；`subscribe` 为间隔轮询，实例列表变化才回调
| `EtcdDiscovery` | `hosts`、`prefix?`（默认 `/flovven/discovery`）、`ttlSeconds?`（默认 30） | 键结构 `{prefix}/{serviceName}/{instanceId}`，值为实例 JSON；注册时挂租约自动续期，`subscribe` 监听前缀的 `put` / `delete` 后重新拉取
|===

`resolve` 返回结果只做数据结构归一化，是否会过滤不健康实例由各实现决定
（Eureka 以 `status === 'UP'` 标记 `healthy`，Nacos 取实例自身 `healthy` 字段）。

== 配置驱动的自动注册（autoreg）

`src/autoreg.ts` 对标 `bufgot/discovery/autoreg` 的 `BootstrapAutoReg`，
把「读配置 → 批量建连 → 注册本机实例 → 起心跳 → 按依赖发现 → 配置变更动态增删」
收敛为一个入口函数，业务侧无需自己 new 各种 provider。

=== 配置结构

[source,yaml]
----
discovery:
  instance:                       # 本机实例身份
    service_name: order-service   # 必填
    ip: 10.0.0.5                  # 必填
    port: 9000
    instance_id: 10.0.0.5:9000    # 可选，缺省 ip:port
    metadata: { version: 0.1.0 }
  registries:                     # 段键名即注册中心别名，type 缺省按键名推断
    etcd:
      endpoints: ["http://127.0.0.1:2379"]
      prefix: /flovven/discovery  # 可选
      heartbeat_ms: 30000         # 心跳/租约节奏，<=0 关闭框架层心跳
    nacos:
      server_addr: 127.0.0.1:8848
      namespace: public
    eureka:
      server_url: http://127.0.0.1:8761/eureka
      enabled: true               # false 等同移除
  dependencies: [user-service, pay-service]
----

配置字段同时接受 camelCase（`serverUrl` / `serverAddr` / `heartbeatMs`）与 bufgot 风格的
snake_case（`server_url` / `server_addr` / `heartbeat_interval`）。
`registries` 中支持任意多个段，类型不限于三个内置实现——通过 `factory` 注入自定义 provider 即可。

=== 使用

[source,ts]
----
import { bootstrapAutoReg } from '@flovven/discovery';

// config 可为对象、discovery 段本身，或返回配置的同步/异步函数（配置中心推送后重读）
const app = await bootstrapAutoReg({
  config: () => config.snapshot(),   // 读取完整配置对象（含 discovery 段）
  configKey: 'discovery',            // 缺省即 discovery
  onFailure: (f) => console.warn(f.registry, f.phase, f.message),
});

app.status();
// { instance, revision, registries: [{ name, type, enabled, registered, heartbeats }],
//   dependencies: [{ serviceName, instances, error }], failures: [] }

// 配置中心推送变更后对账：新增即注册、移除即注销、改动先注销再重建
const report = await app.reload();
// { revision, added, removed, kept, dependencies, failures, ok }

// 跨注册中心发现（按 id 去重合并，单源失败跳过）
const instances = await app.discover('user-service');

// 优雅下线：全部注销 + 停心跳 + 关连接
await app.close();
----

=== 行为约定

[options="header"]
|===
| 场景 | 行为

| 新增注册中心段 | 建连 → `register` → 按 `heartbeat_ms`（缺省 30000）起续约定时器
| 移除段 / `enabled: false` | 先 `deregister` 再 `close`，同时清掉续约定时器
| 段配置变更 | 按旧配置注销并关闭，再按新配置重建（`reload()` 报告中同时计入 removed 与 added）
| 单源失败 | 记录到 `failures`（`phase` 为 `config` / `connect` / `register` / `deregister` / `renew` / `discover`），其余注册中心照常工作，入口函数不抛出
| 心跳续约 | 优先调用 provider 的 `renew()`；无该能力时退化为再次 `register()`
| `dependencies` | bootstrap 后自动执行一次发现，结果缓存在 `status().dependencies`，可再次 `discoverDependencies()` 刷新
|===

=== 扩展点

* `factory(ctx) => provider`：`ctx` 含 `name` / `type` / `config` / `instance` / `heartbeatMs`；
  返回对象除标准 `ServiceDiscovery` 外可选实现 `renew()`、`close()`。测试用它注入 mock，业务侧可接入自研注册中心。
* `createDiscoveryProvider`：缺省工厂，按 `type` 创建 `EtcdDiscovery` / `EurekaDiscovery` / `NacosDiscovery`。
* `onFailure` / `logger`：错误聚合的消费端；`allFailures()` / `clearFailures()` 可整体读取与重置。
* 辅助函数：`extractConfigSection`（取段）、`resolveRegistryType`（类型推断）、
  `isRegistryEnabled`（连接条件判断）、`resolveHeartbeatMs`（心跳间隔解析）。

== 与 web-client 配合

`@flovven/web-client` 的 `discoverer` 选项接受任意实现或 `{ resolve(name) }` 鸭子类型对象，
因此可直接把本包实例传入，客户端据此做服务名解析与负载均衡：

[source,ts]
----
import { createClient } from '@flovven/web-client';
import { EtcdDiscovery } from '@flovven/discovery';

const discovery = new EtcdDiscovery({ hosts: 'http://127.0.0.1:2379' });

const svc = createClient({
  serviceName: 'user-service',
  discoverer: discovery,
  mappings: { get: 'GET /api/users/{id}' },
});
----
